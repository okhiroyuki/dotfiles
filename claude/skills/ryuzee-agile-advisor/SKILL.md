# ryuzee アジャイル助言

ryuzee.com のブログ記事を一次情報として、アジャイル開発の課題に助言する。
助言は筆者の見解に基づくものとして扱い、事実と見解を区別して返す。

## 手順

1. **関連記事を探す**: `references/index.tsv`（id・日付・タイトル・タグ・URL）をキーワードで検索する。タイトルとタグの両方が対象。
   例: `rg -i "バックログ|リファインメント" ~/.claude/skills/ryuzee-agile-advisor/references/index.tsv`
   タイトルやタグに出ない語は、類義語も並べて検索する（例: 見積もり → 見積、ベロシティ）。
   索引は本文を含まないため、「記事がない」と判断するのは、類義語で検索しても該当がなく、候補になりそうな記事の本文を確認した後に限る。
2. **本文を取得する**: 関連が強い記事を最大3件まで選び、取得する。
   `python3 ~/.claude/skills/ryuzee-agile-advisor/scripts/fetch_article.py <id> [<id> ...]`
   4件以上必要なときは `explore` subagent に取得と要約を委譲し、要点だけ受け取る。
3. **助言を組み立てる**: ユーザーの状況に当てはめ、次の形で返す。
   - 結論（1〜2文）
   - 根拠: 記事ごとに「記事タイトル（日付）」と要点を書く。URL を必ず付ける
   - ユーザーの状況への適用案（小さく試せる行動を1〜3個）
   - 前提と限界: 状況が違えば当てはまらない点、記事が古い可能性がある点（生成AI関連は特に）
4. **記事にない場合**: 「ryuzee の記事には該当する記述が見つからなかった」と明言する。その場合のみ、一般論として補足し、一般論であることを明記する。

## スクラムガイドの質問

スクラムの定義・役割（開発者、プロダクトオーナー、スクラムマスター）・イベント・作成物と確約など、ルールに関する質問は次の順で答える。

1. `references/scrum-guide-2020-ja.md` の見出しを `rg -n "^#" <そのパス>` で確認し、該当節を読む。
2. 結論・根拠（ガイドの節名）・適用・限界の順で書く。ガイドの記述と、ryuzee の記事の見解は分けて示す。
3. ガイドは「何を・なぜ」を定め、「どのように」は開発者の裁量に任せる部分が多い。その境界を明記する。

## 成功基準（MUST）

- 助言の根拠として、少なくとも1件の記事 URL と日付を示している
- 記事の本文を引用する場合は短い抜粋（1段落未満）にとどめ、全文を貼らない
- 事実（記事に書かれたこと）と、ユーザー状況への推論を区別して書いている
- 索引に無いテーマで記事を捏造していない
- 同じ助言を3回以上書く前に、関連記事が本当に存在するか確認している

## 導入（dotfiles を pull した後）

- `rcup` を実行する。これで `~/.claude/skills/ryuzee-agile-advisor` にリンクが張られる。`rcup` せずに別の場所へ置くと、本文のパス例が合わなくなる。
- 前提: Python 3.9 以上（標準ライブラリのみ）、`www.ryuzee.com` への通信。

## 注意

- `index.tsv` は取得時点のスナップショット。最新記事が無いことがある。最新性が重要な場合は `scripts/build_index.py` で再生成する（記事数に比例して数分。サイトに負荷をかけないよう 0.5 秒間隔で巡回する）。
- 本文は保存しない。記事の内容を再配布しない。
- 記事の本文が取得できない（`本文が見つからない`）場合は、その記事を根拠にせず、URL を案内するだけにする。
