# 日本語の社内向け文書を推敲する

対象は、企画、開発、営業、CS、運用、経営など、複数の職種が読むまとまった社内文書である。
主用途は既存文書の推敲・リライトであり、新規作成にも適用する。

目的は文章をきれいにすることではない。
読み手が共通の前提に立ち、論点を理解し、判断できる状態をつくることである。

文書全体の種別、節の構成、分割、順序は `cognitive-load-docs` に任せる。
このスキルは文、段落、見出しの文言と、文章の事実性・明確さを扱う。

## 必須

次の4つは、短さや文体より優先する。

- **情報の状態を混同しない**：事実、解釈、提案、未確認事項を、根拠に応じた強さで書く。
- **用語を定義する**：定着した用語と略語だけを使い、読み手に共有されていない語は初出で定義する。文書内だけの略語は作らない。
- **参照先を復元できるようにする**：指示語、修飾語、固有名、他文書への参照は、読み手が必要な対象を特定できる形にする。
- **必要な因果を残す**：結果だけでは復元できない因果は、読み手が理解に必要とする途中の段を残す。

## 推敲の順序

1. 読み手と文書の目的を確認する。読み手が不明なら複数職種の社内読者を仮定し、その仮定を変更メモに残す。
2. 元文書の最新版と、引き継ぐ事実の出典を確認する。
3. 用語、定着略語、確定事項、未確認事項を整理する。
4. 判断に必要な前提、対象、因果を残す。元文書にない事実や例は追加しない。
5. 同じ粒度の重複と明らかな作業メモを削る。概要と詳細のように役割や粒度が異なる説明は残してよい。
6. 文、段落、見出し、表記を整える。文体は用途や社内慣行に合わせ、文書内で統一する。
7. 本文に加えて、仮定、未確認事項、意味に影響する変更、削除した作業メモ・重複を短く報告する。

## 強度

- **必須**：このファイルの4規則。textlintの指摘より優先する。
- **推奨**：段落の整理、冗長な言い換えの削除、具体的な語への置き換え、読み手のための最小限の道案内。
- **状況依存**：文の長さ、太字、脚注、箇条書き、修辞、Markdownの細かな整形。

## 完了前の確認

- [ ] 必須4規則を満たしている。
- [ ] 目安を守るために、必要な文脈や因果を削っていない。
- [ ] 同じ粒度の重複と作業メモだけを削っている。
- [ ] 未確認事項と意味に影響する変更を報告している。
