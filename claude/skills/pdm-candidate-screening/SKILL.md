# PdM 候補者の書類評価と面談準備

## 目的

同じ PdM 職の候補者を、毎回同じ観点・同じ基準で見られるようにする。
書類から言えることと言えないことを分け、言えないことを面談の質問に変える。

## 原則

- MUST: 評価には、書類のどの記述から判断したかを添える。印象だけの評価を書かない
- MUST: 書類に材料がない観点は評価を付けず「面談で確認」とする。推測で埋めない
- MUST: 年齢・性別・国籍・出身地・家族構成・学歴の銘柄・ブランク期間の有無そのものを、評価や質問の材料にしない（厚労省「公正な採用選考の基本」に沿う）。ブランクは理由を詮索せず、その前後の仕事内容だけを見る
- MUST: 候補者の書類の内容を、このリポジトリ・llm-wiki・メモリに保存しない
- SHOULD:「何を作ったか」より「何が変わったか」「なぜそれを選んだか」を重く見る
- SHOULD:「チームで達成した」記述は、本人が担った判断がどこかを面談の論点にする

## 評価観点

観点の定義、想定している領域、書類で見るシグナル、レベル別の期待値、深掘り質問の例は
[references/criteria.md](references/criteria.md) にある。評価前に MUST で読み込む。
`references/domain-examples.md` があれば、業界固有の具体例として併せて読む（ローカル環境にだけ置くファイルで、ない環境もある）。

観点は 3 群 13 個で固定する。記号と名前を変えない。

- A. 境界型: A1 ソフトとハードの境界の理解 / A2 物理的なデリバリーの設計 / A3 規制・ガイドラインの要件化 / A4 物理的な制約の中での判断
- B. 枠組み型: B1 構造化・抽象化 / B2 進め方の設計 / B3 伝え方 / B4 具体への降り方
- C. PdM 共通: C1 課題発見・顧客理解 / C2 成果志向 / C3 優先順位付け / C4 合意形成 / C5 振り返り・再現性

どの候補者も全観点で評価し、境界型・枠組み型のどちらに寄っているかを判定する。

## 進め方

1. 書類を受け取る。募集ポジションの想定レベル（例: PdM / シニア / リード）と、どちらの型を優先したいかを確認する。分からなければ「PdM（中堅）・型の優先なし」を仮定し、仮定したことを出力に明記する
2. `references/criteria.md`（と、あれば `references/domain-examples.md`）を読み込む
3. 書類から観点ごとに該当する記述を抜き出し、評価を付ける（評価の目盛りは criteria.md に従う）
4. A 群・B 群の評価から型の向きを判定する。判定の考え方は criteria.md の「2 つの型」に従う
5. 懸念点（レッドフラグ）を criteria.md の一覧と照らして挙げる
6. 評価が「？」または低い観点、懸念点を優先して、面談の論点と質問を作る。質問は 1 論点につき「最初の問い」と「深掘り」をセットにする。向きの判定が書類だけで決まらない場合は、それを確かめる論点を最優先にする
7. 下記の出力形式でまとめる

## 出力形式

```markdown
## サマリー

（3 行以内。型の向き・強み・最大の懸念・面談で最優先で確かめること）

前提: 想定レベル = ○○ / 優先する型 = ○○（仮定の場合はその旨）

## 型の向き

境界型寄り / 枠組み型寄り / 両方 / どちらも材料不足
（判定の理由を 2〜3 行。枠組み型寄りなら B4 の評価に必ず触れる）

## 観点別評価

| 観点                                    | 評価 | 根拠（書類の記述） | 面談で確認すること |
| --------------------------------------- | ---- | ------------------ | ------------------ |
| （A1〜A4、B1〜B4、C1〜C5 の順に 13 行） |      |                    |                    |

## 懸念点

- 懸念: … / 根拠: … / 面談での確かめ方: …

## 面談の論点と質問案（優先順）

### 1. 論点名（対応する観点）

- 最初の問い: …
- 深掘り: …（答えが抽象的だった場合）
- 良い回答の兆候: …
```

面談時間が指定されていれば、論点の数をその時間に収まるよう絞る（目安: 1 論点 10 分）。

## 成功基準

- 13 観点すべてに評価または「？」が付いている
- 評価が付いた観点には、書類の具体的な記述が根拠として引用されている
- 型の向きが判定され、その理由が A 群・B 群の評価と矛盾していない
- Web 上で完結する経験だけの候補者を、それだけを理由に見送り扱いしていない
- 年齢・性別・家族・出身地などに触れる評価や質問が含まれていない
- 面談の質問が、懸念点または判断できなかった観点に対応している
- 合否を断定していない（「通過推奨」等を書く場合も根拠と留保を添える）
