# Structure

構成と論理だけを読む。主張と根拠の対応、因果の飛躍、段落や見出しの順序、同じ内容を同じ詳しさで繰り返している箇所、必要な前提の欠落、宣言した個数と項目数の不一致、一つの節の中で事実と判断が混ざっている箇所を指摘する。
概要と詳細のように詳しさが異なる繰り返しと、判断に必要な途中の因果は指摘しない。表層の日本語表現は指摘しない。
文書自身が PRD または要件定義書であると示している場合は、なぜやるか・何をするかの記述に実装方法や技術選定が混ざっている箇所と、未確定の内容を結論として書いている箇所も指摘する。文書種別が分からない場合は、この確認をしない。
修正案では、原文にない効果、指標、手順、運用条件を根拠なしに追加しない。不足する前提は、追加を断定せず確認事項として示す。
